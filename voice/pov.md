# Patrick's POV — recurring topics

Reference material for post drafting. These are Patrick's positions in his own words. When generating drafts on these topics, tune to these takes.

---

## 1. Signals

**Position:** Big fan of signals as a category — they're incredibly valuable for getting info on prospects, acting on it, and prioritizing accounts.

**What most people get wrong:** They chase the signals that mainstream GTM content advertises most — job changes, fundraising announcements, Google search intent. Those aren't actually helpful.

**What's actually valuable:** "Alpha" signals — ones nobody else in your space has thought of generating yet. Requires creativity.

**Concrete example used:** Sentrion — a tool that uses LLMs to extract really interesting insights from job listings (tools a company uses, moves they're planning, office expansions).

**Takeaway:** Generate novel signals. Don't just plug in the obvious ones.

## 2. AI SDRs / the future of BDR work

**Position:** Let BDRs and SDRs do what they do best — be people. Not bullish on AI SDRs right now, though they'll get there eventually.

**Hard line:** Cold calling is something I would *never* recommend an AI try to take over. Human-to-human contact is so integral to sales that I don't think most sales roles will be jeopardized by AI any time soon.

**Nuance:** A lot of the AI SDR tools are so black-boxed it doesn't make sense to set them up. Could see them being somewhat valuable for smaller startups.

**Consistent thread with earlier posts:** AI is a supplement, not a replacement. Clients don't want to fire BDRs — they want them to sell more.

## 3. Outbound in 2026

**Position:** Rapidly transforming channel. No single answer.

**Email:** Getting worse. Results dropping significantly, especially where AI is accelerating fast. Still works in some regards — not dead, but decelerating.

**LinkedIn:** Still works very well as a channel. Caveat: many tools technically violate LinkedIn's guidelines. If you can do it scalably without getting banned, great. Otherwise, stay away.

**Bigger structural take:** Outbound is getting harder because value-adding assets can be generated at scale cheaply now. Research + custom asset in a message used to be impossible to do at scale. Now anyone with Claude Code or Clay can do it. Standing out gets harder as the floor rises.

**Bullish on:** Gifting. Can't be cheaply automated, still costs money, takes thoughtful time. Sendoso is a favorite tool for this.

## 4. Will Claude Code replace Clay?

Unpublished long-form take saved as `linkedin/drafts/claude-code-vs-clay.md`. Short version:

- Clay's moats: data marketplace, 100k+ row scale engineering, compliant interface.
- Claude Code's strengths: best models, cheap workflows, easy tool/data provider connections, Supabase + Sheets can mimic Clay's interface.
- Three questions determine the answer: **compliance** (Claude Code loses for enterprise Salesforce/Snowflake/Outreach integrations), **data** (toss-up — depends on provider), **engineering** (use-case based; Claude Code struggles with complex conditional workflows).
- Current verdict: **Not a good replacement for enterprise, for most things.** OK for startups on simpler workflows. Robust CRM enrichment or complex inbound lead workflows → Clay. Quick list enrichment or massive per-table action counts → Claude Code + good APIs.
- Future: Clay will likely release something to make it Claude-friendly; Claude will likely release data enrichments and charge per API call.

## 6. The GTM Engineering discipline

**Definition:** An AI-forward role that strategically builds workflows and automates aspects of marketing, sales, and RevOps — all under the GTM umbrella.

**Who learns it fastest:** People with technical backgrounds. But — people with sales or less-technical backgrounds can learn it well and bring a more nuanced understanding because they've operated in the parts of the org GTMEs do work in.

**Where the discipline is heading:** Toward a Claude-based ecosystem. Clay initially coined "GTM engineering" and most workflows were built there, but the future stack is **Clay + N8N + Claude Code** as the core automation tools.

**Thesis:** Claude Code becomes the terminal/home for GTM engineers. Runs high-scale enrichment, workflows, scheduled tasks.

**Growth outlook:** GTME will continue to grow and thrive. The need is massive and the value when installed correctly is huge.
